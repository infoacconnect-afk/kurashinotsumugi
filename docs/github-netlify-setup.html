INTRO

はじめに｜GitHubってなに？

GitHub（ギットハブ）は、世界中の開発者が使う「ファイル置き場」のようなサービスです。無料で、Microsoft社が運営していて、信頼性は世界最高レベルです。

GitHub連携で何ができるようになる？

現在（ドラッグ&ドロップ）GitHub連携後
サイト更新 ZIP解凍 → Netlifyにドラッグ GitHubに置くだけで自動
microCMS記事公開 制作会社に依頼が必要 公開ボタン1つで自動反映
変更履歴 残らない すべての変更が履歴として残る
間違えたとき 復元困難 いつでも過去の状態に戻せる
複数人で編集 難しい 簡単

SIGN UP

GitHubアカウント作成

所要時間: 10分

  1. GitHub公式サイトを開く

    https://github.com/signup

  2. メールアドレスを入力

    会社のメール（例: info@ac-c.co.jp）をおすすめします。引き継ぎ時に便利です。

  3. パスワードを設定

    15文字以上・大文字/小文字/数字/記号を混ぜたもの

  4. ユーザー名を決める

    他の人と重複しない半角英数字。例:

    • ac-connect
    • kurashinotsumugi
    • ac-connect-jp

    このユーザー名はURL の一部になります（例: github.com/ac-connect）

  5. 「y/n」の質問（メール受信）

    お知らせメールを受け取るかの確認。「n」でOKです。

  6. パズル認証

    「私はロボットではありません」的なパズルを解いてください。

  7. 「Create account」をクリック

    メールに認証コード（6桁）が届くので、画面に入力してください。

  8. アンケート画面（英語）

    下記のように答えれば大丈夫です:

    • How many team members? → Just me
    • What features? → 何も選ばず「Continue」でOK
    • What do you plan to use GitHub for? → Other や Manage code and collaborate どちらでも

    最後に Free plan（無料プラン） を選択して完了 🎉

🌱 完了の目印

ダッシュボード（左に「Top Repositories」、中央に「Start a new repository」ボタンがある画面）が表示されればOK。

2
REPO

リポジトリ（ファイル置き場）を作る

所要時間: 5分

リポジトリ（英: repository）は「保管庫」の意味。今回のサイトファイル一式を入れる場所を作ります。

  1. 右上の「＋」→「New repository」をクリック

    または、中央の 「Create repository」 の緑ボタンでもOK

  2. リポジトリの情報を入力

    Create a new repository
    Owner:ac-connect ← あなたのユーザー名
    Repository name:kurashinotsumugi
    Description:くらしのつむぎ ブランドサイト
    公開設定: 🟢 Public（公開）または 🔒 Private（非公開）
    Initialize:☑️ Add a README file にチェック
    Create repository
🤔 Public と Private の違い

Public（公開）: 誰でもソースコードを見られる。多くの企業や個人が公開している普通の状態。GitHubの慣例に沿っている。

Private（非公開）: あなたと招待した人だけが見られる。有料プラン扱いになる場合あり（無料枠内で使えることも多い）。

今回のような通常のブランドサイトのソースコードは、Publicで問題ありません。APIキーなど秘密情報はそもそもGitHubに置きません（環境変数で管理）。

迷ったら Publicで。

⚠️ .gitignore について

「Add .gitignore」というオプションが出た場合、「None」を選択してください。

また、「Choose a license」も「None」で大丈夫です。

3
UPLOAD

サイトファイルをアップロード

所要時間: 10分

先ほど作ったリポジトリに、くらしのつむぎのサイトファイル一式をアップロードします。

  1. リポジトリ画面を開く

    今作ったリポジトリのページ（github.com/あなたのユーザー名/kurashinotsumugi）にいる状態です。

  2. 「Add file」→「Upload files」を選択

    画面上部（README.mdの上あたり）に 「Add file」 というボタンがあります。

    クリック → 「Upload files」 を選択

  3. サイトファイルをドラッグ&ドロップ

    手元にある くらしのつむぎサイトのフォルダを開き、中身のファイル・フォルダをすべて選択して、GitHubのアップロード枠にドラッグ&ドロップしてください。

    ⚠️ 大事なポイント

    「フォルダごと」ではなく、フォルダの中身を全部選択してドラッグしてください。

    OK例: index.html, korekara.html, sorekara.html, ..., assets/, data/, build/, docs/ を選択してドラッグ

    NG例: kurashinotsumugi/ フォルダごとドラッグ（余計な階層が1つ増えてしまいます）

  4. アップロード完了を待つ

    ファイル数が多いので、1〜2分かかります。進行状況が緑のバーで表示されます。

  5. コミットメッセージを入力

    ページを下にスクロールすると、以下の入力欄があります:

    Commit changes
    Initial upload of kurashinotsumugi site
    ◉ Commit directly to the main branch
    Commit changes

    コミットメッセージは「Initial upload」や「サイト初期アップロード」など、内容が分かる短い文で大丈夫です。

  6. アップロード完了を確認

    リポジトリのトップページに戻り、以下のファイルが表示されればOK:

    • index.html
    • korekara.html
    • sorekara.html
    • lab.html
    • assets/
    • data/
    • build/
    • docs/
    • その他HTML等
🌱 完了の目印

GitHubのリポジトリ画面で、index.htmlをクリックしてHTMLコードが表示されればアップロード成功です。

4
CONNECT

Netlifyとつなぐ

所要時間: 10分

いよいよ、GitHubとNetlifyを連携させます。連携ができれば、GitHubに変更を加えるたびにNetlifyが自動で反映してくれるようになります。

  1. Netlifyにログイン

    https://app.netlify.com/

  2. 「Add new site」→「Import an existing project」

    ダッシュボードの右上または中央にある 「Add new site」 をクリック

    3つの選択肢が出ますが、「Import an existing project」を選択

  3. 「Deploy with GitHub」をクリック

    GitLab / Bitbucket などの選択肢もありますが、GitHubを選択

  4. GitHubとの連携を承認

    GitHubのログイン画面に遷移し、「Authorize Netlify」という緑ボタンをクリック

    「どのリポジトリを見せる？」と聞かれた場合:

    • 「Only select repositories」を選び、kurashinotsumugiのみを選択
    • （All repositoriesでも動きますが、Only selectの方が安全です）

    「Install」をクリック

  5. Netlifyでリポジトリを選択

    Netlifyの画面に戻り、リポジトリ一覧が表示されます。kurashinotsumugiをクリック

  6. ビルド設定画面が表示される（← ここが Build settings！）

    ようやくお探しだった画面です 🎉

    Deploy settings for kurashinotsumugi
    Branch to deploy:main
    Base directory:（空欄でOK）
    Build command:node build/fetch-lab.mjs
    Publish directory:.
    Deploy site
    項目入力値
    Branch to deploymain（デフォルトのまま）
    Base directory空欄
    Build commandnode build/fetch-lab.mjs
    Publish directory.（ドットひとつ）
    🌱 補足：Build commandについて

    今の時点では、まだmicroCMSが未接続なので、node build/fetch-lab.mjsを実行してもエラーになります。

    そこで今回は、Build commandは空欄のままにしておくのがおすすめです。microCMS連携時に改めて設定します。

    👉 Build command: （空欄）で「Deploy site」をクリックしてください。

  7. 「Deploy site」をクリック

    Netlifyが自動で:

    1. GitHubからファイルをダウンロード
    2. サイトを公開
    3. 仮URLを発行

    1〜2分待つと、xxx.netlify.app の仮URLが発行され、サイトが表示されます。

SWAP

古い方のサイトを削除・入れ替え

所要時間: 5分

今、Netlify上には 2つのサイト が存在する状態のはずです:

  1. 古い方: ドラッグ&ドロップで公開したサイト（kurashinotsumugi.comが繋がっている）
  2. 新しい方: GitHub連携で公開したサイト（仮URLだけ）

「新しい方」に kurashinotsumugi.com を付け替えます。

  1. 古い方のサイトからドメインを外す

    Netlifyダッシュボードで古い方のサイトを開く

    「Domain settings」または「Domains」を開く

    kurashinotsumugi.comとwww.kurashinotsumugi.comの右端「⋯」→ 「Remove domain」

    両方削除してください。

  2. 新しい方のサイトにドメインを追加

    Netlifyダッシュボードで新しい方のサイト（GitHub連携で作った方）を開く

    「Domain settings」→「Add a domain」または「Add custom domain」

    kurashinotsumugi.comを入力 → 「Verify」 → 「Yes, add domain」

    www バージョンも自動で追加されます。

  3. SSL証明書の再発行を待つ（数分）

    ドメインの付け替えなので、SSL証明書も自動で新しいサイトに紐づけ直されます。数分待つと「Let's Encrypt certificate」がactiveになります。

  4. 「Force HTTPS」を有効化

    HTTPSセクションの「Force HTTPS」トグルをONにしてください。

  5. 古い方のサイトを削除

    古い方のサイト画面 → 「Site settings」→ 一番下までスクロール → 「Delete this site」

    確認ダイアログでサイト名を入力して削除完了。

    ⚠️ ゆっくり進めても大丈夫

    不安なら、古い方のサイトはすぐ削除せず数日〜1週間残しておくのもOK。新しい方が問題なく動いてから削除しても遅くありません。

DAILY OPS

今後の運用

ケース①: サイトの文言や画像を修正したい

  1. 制作会社から新しいファイルを受け取る
  2. GitHubリポジトリで該当ファイルを開く → 右上の 「✏️」（鉛筆マーク）で編集
  3. または、「Add file」→「Upload files」で上書きアップロード
  4. コミットして保存 → 1〜2分で本番反映

ケース②: microCMSで記事を書きたい

  1. microCMSにログイン → 記事作成 → 「公開」ボタン
  2. Webhookが発火 → Netlifyが自動ビルド → 2〜3分で本番反映
  3. あなたは何もしなくてOKです 🌱

ケース③: 過去の状態に戻したい

  1. Netlifyの「Deploys」タブを開く
  2. 戻したい過去のデプロイをクリック → 「Publish deploy」
  3. 数秒で過去の状態に戻ります
🌱 覚えておいてほしいこと

これからは「GitHubに置くこと」＝「本番サイトに公開すること」と覚えてください。

逆に言うと、GitHubで編集した瞬間から本番に反映されるので、慎重に。

不安な場合は「Branchを分けてプレビュー」という上級テクニックもありますが、必要になったら別途ご案内します。

HELP

FAQ｜困ったときは

Q. GitHubにログインしたら、変な英語のダッシュボードが出て怖いです

A. GitHubのUIは開発者向けで、初見だと圧倒されがちです。慣れないうちは、以下だけ覚えれば大丈夫:

  • 「Repositories」→ 自分の保管庫一覧
  • 「＋」（右上）→ 新規作成メニュー
  • 「Settings」→ アカウント設定

ブラウザの翻訳機能で日本語化することもできます。

Q. GitHubにアップロードしたのに、Netlifyにサイトが反映されません

A. 以下を確認:

  1. NetlifyのDeploysタブに新しいデプロイが表示されているか
  2. デプロイが「Failed」になっていないか（クリックしてログを確認）
  3. NetlifyとGitHubの連携が有効か（Site settings → Build & deploy）

Q. GitHubのファイルを間違えて削除してしまいました

A. 慌てないでください。GitHubはすべての履歴が残っています。

  1. リポジトリ画面 → 上部の 「Commits」（〇〇 commits と書いてある部分）をクリック
  2. 削除前のコミットを見つけて開く
  3. ファイルを再度アップロードすれば復元完了

Q. リポジトリを「Private」で作ってしまいました。Publicに変えるには？

A. リポジトリ → 「Settings」→ 一番下までスクロール → 「Change visibility」→ Publicに変更。逆も可能です。

Q. Build command「node build/fetch-lab.mjs」を今すぐ設定するとどうなる？

A. microCMSの環境変数が未設定なので、ビルドが失敗します。今は空欄で進めて、microCMS設定時に「Site settings → Build & deploy → Build settings → Edit settings」から追記してください。この時、この画面が今回設定した本来の「Build settings」画面です。

Q. GitHubの容量制限はある？

A. 無料プランで:

  • 1リポジトリあたり 5GB推奨（技術的には制限なし）
  • 1ファイルあたり 100MBまで

くらしのつむぎサイトの規模なら余裕です（数MBのはず）。
