INTRO

はじめに｜全体像

「住資産再生ラボ」の記事は、以下の流れで運用します。

┌──────────────────────┐
│  microCMS管理画面（執筆） │
│  ・記事作成                │
│  ・下書き保存 / 公開       │
└──────┬───────────────┘
       │ 公開ボタンを押す
       ▼
┌──────────────────────┐
│  Webhook トリガー          │
│  (microCMSからNetlifyへ)   │
└──────┬───────────────┘
       │
       ▼
┌──────────────────────┐
│  Netlify / Vercel でビルド │
│  ・fetch-lab.mjs 実行     │
│  ・articles.json 生成     │
│  ・サイト再デプロイ        │
└──────┬───────────────┘
       │ 約2〜3分
       ▼
┌──────────────────────┐
│  本番サイトに記事が反映     │
│  くらしのつむぎ / 住資産...  │
└──────────────────────┘
🌱 ポイント

執筆者はmicroCMSの管理画面だけを触れば大丈夫です。コードやサーバー操作は必要ありません。「新規追加」→「タイトルと本文を書く」→「公開する」の3ステップで、記事が本番サイトに反映されます。

1
SETUP

microCMSアカウント準備

① アカウントを作る

  1. microCMSの新規登録ページからアカウントを作成
  2. ログイン後、「サービスを作る」を選択
  3. 以下の情報でサービスを作成:
サービス名くらしのつむぎ（任意で変更可）
サービスIDkurashi-tsumugi（推奨。半角英数）
これがドメインの一部になります: kurashi-tsumugi.microcms.io
プランHobby（無料）から開始で問題ありません。記事数が増えたら Team プランを検討
💡 プランの目安

Hobby (無料): 記事数10件・APIリクエスト1万回/月まで（お試しに最適）
Team (¥4,900/月): 記事数無制限・複数編集者・下書き共有機能あり（本格運用に）

2
SCHEMA

APIの作成（articles スキーマ設計）

サービスができたら、次に「API」を作ります。ここでいう API とは、記事を保存する箱のようなものです。

① APIを新規作成

  1. 管理画面左メニュー → 「＋APIを作成」
  2. 以下のとおり設定:
API名記事
エンドポイントarticles（必ずこの名前）
APIの型リスト形式を選択

② APIスキーマ（フィールド）を作成

下記12個のフィールドを、上から順番に追加してください。順番も揃えると管理画面が使いやすくなります。

フィールドID 表示名 種類 必須 説明
title タイトル テキストフィールド 必須 記事タイトル。40文字以内が望ましい
slug スラッグ (URL用ID) テキストフィールド 必須 URLに使う半角英数字。例: jikka-souzoku-5steps
category カテゴリ セレクトフィールド 必須 5つから1つ選択（次章参照）
excerpt 抜粋文 テキストエリア 必須 一覧に表示される導入文。80〜120文字が理想
body 本文 リッチエディタ 必須 記事本文。見出し(h2/h3)・段落・画像・引用・箇条書き・番号リスト・表を使えます
eyecatch アイキャッチ画像 画像 任意 記事ヘッダーの大きな画像。推奨サイズ: 1200×675px（16:9）
eyecatchAlt 画像の代替テキスト テキストフィールド 任意 画像が読めない環境での説明文。SEOにも寄与
author 執筆者 テキストフィールド 任意 デフォルト値: くらしのつむぎ編集部
isPickup ピックアップに表示する 真偽値（ブール） 任意 ONにするとラボトップの上部で強調表示。常に1本のみONを推奨
isPopular 人気記事に表示する 真偽値（ブール） 任意 ONにすると「よく読まれている記事」に含まれる
views 閲覧数（手動） 数値 任意 人気記事の並び順に使用。実測値でも概算でもOK
publishedAt 公開日時 — 自動 microCMSが自動で管理（手動フィールド作成不要）
⚠️ フィールドIDは正確に

フィールドID（左端のコード欄）は、表の値を一字一句そのまま入力してください。1文字でも違うと、サイト側でデータを認識できなくなります。表示名（真ん中）は日本語でOKです。

3
CATEGORY

カテゴリの入力ルール

category のセレクトフィールドには、次の5つの値だけを選択肢として登録してください。値（value）は必ず半角英数字で、下記の通りにしてください。

akiya 🌾 空き家情報
souzoku 📜 相続・税金・管理・活用
jirei 🏡 再生・活用事例
torikumi 🌿 取組紹介
kensaku 🔍 活用物件検索

設定手順

  1. APIスキーマ画面で category フィールドを編集
  2. 「選択肢の一覧」に、上記5つの英字コードを1行ずつ登録
  3. 「複数選択」は OFF（1記事1カテゴリ）
  4. デフォルト値: akiya
🌱 なぜ英字なのか

サイト側で「カテゴリ名の表示」と「絞り込みロジック」を切り分けるためです。将来「カテゴリ名を少し変えたい」場合、サイト側の設定ファイルを変えるだけで、既存記事のデータを触らずに更新できるようになります。

4
API KEY

APIキーの発行

ここで APIキー（データを取得するための鍵）を発行します。このキーは、ブラウザには一切公開されません。ホスティングサービス側だけに保管します。

  1. 管理画面 → 「サービス設定」→「APIキー管理」
  2. 「APIキーを作成」ボタン
  3. 以下の権限だけをONにする:
    • ✅ GET（取得のみ）
    • ❌ POST / PUT / PATCH / DELETE（すべてOFF）
  4. キー名: build-server（識別用の名前）
  5. 発行されたキーを安全な場所に保管（例: パスワード管理ツール）
🔒 APIキーの取り扱い（超重要）

APIキーは、絶対にコードに直接書かないでください。GitHub、Slack、メール本文などにも貼らないでください。

キーが漏れると、記事の情報を第三者に読まれる可能性があります。

もしキーが漏れた場合は、すぐにmicroCMSで該当キーを削除→新規発行してください。

5
DEPLOY

ホスティング側の設定（ビルド連携）

ここではくらしのつむぎサイトが Netlify にホスティングされている前提で説明します。Vercel / Cloudflare Pages でもほぼ同じ手順です。

① Netlify にサイトを接続

すでに接続済みの場合はスキップしてください。未接続の場合は、GitHubリポジトリを Netlify に紐づけます。

② 環境変数を設定

  1. Netlify管理画面 → 該当サイト → Site settings → Environment variables
  2. 以下の2つを追加:
キー値
MICROCMS_SERVICE_DOMAIN microCMSのサービスID（例: kurashi-tsumugi）
MICROCMS_API_KEY STEP 4 で発行したGET用APIキー

③ ビルドコマンドを設定

Site settings → Build & deploy → Build settings で、Build command を以下に変更:

node build/fetch-lab.mjs

Publish directory は既存のまま（プロジェクトのルート、または . ）です。

🌱 ビルド後の確認

デプロイ後、https://your-site.netlify.app/data/articles.json にアクセスして、記事データが読めれば成功です。（本番URLに置き換えてください）

6
WEBHOOK

Webhook連携（記事公開の自動反映）

Webhookを設定すると、microCMSで記事を公開した瞬間に、自動的にNetlifyがサイトを再ビルドしてくれます。手作業は不要です。

① Netlify側で「ビルドフック」を発行

  1. Netlify → Site settings → Build & deploy → Build hooks
  2. 「Add build hook」でフックを作成
    • Name: microcms-publish
    • Branch to build: main（本番ブランチ）
  3. 発行された URL（https://api.netlify.com/build_hooks/xxxxxxxx）をコピー

② microCMS側にWebhookを設定

  1. microCMS → APIの管理画面 → API設定 → Webhook
  2. 「Netlify」を選択（Netlify向けのプリセットあり）
  3. 先ほどコピーしたURLを貼り付け
  4. トリガー: 「コンテンツの公開時」と「コンテンツの再公開時」にチェック
  5. 保存
⏱ 反映までの目安

公開ボタンを押してから、本番サイトに反映されるまで約2〜3分です。

反映を確認するには、Netlifyの「Deploys」ページでビルドが「Published」になったかを見るのが確実です。

7
WRITING

記事の書き方（執筆ガイド）

基本の入力手順

  1. 「＋新規追加」から記事を作成

    microCMSダッシュボード → articles → 右上「＋新規追加」

  2. タイトルとスラッグを決める

    スラッグは、記事内容を英語で簡潔に。例:
    「実家を相続したら…」→ jikka-souzoku-guide
    「空き家の固定資産税」→ akiya-kotei-shisan-zei

  3. カテゴリを選ぶ

    5つのカテゴリから、記事の内容にいちばん近いものを1つ選択。

  4. 抜粋文を書く

    一覧ページで表示される導入文。80〜120文字を目安に、記事の魅力が伝わる短い文章を。

  5. 本文を書く

    リッチエディタで自由に。次章の「書き方のコツ」を参考にしてください。

  6. アイキャッチ画像を設定

    1200×675px の画像を推奨。トリミングの目安は「16:9」。

  7. プレビューで確認

    「プレビュー」ボタンで公開前の表示を確認できます。

  8. 「公開」ボタンを押す

    2〜3分後、本番サイトに反映されます。

本文の書き方のコツ

  • H2見出しで章を区切る：目次が自動生成されるので、読者が迷子になりません
  • 1つの段落は3〜4行まで：スマホでも読みやすくなります
  • 専門用語は言い換えを添える：例：「相続税(=引き継いだ財産にかかる税金)」
  • 「〜です」「〜ます」のやさしい調子：くらしのつむぎのトーンを大切に
  • 結論を急がない：「売却が正解」など断定を避け、選択肢を並べる
  • 読み手に寄り添う：「〇〇でお困りではありませんか？」「ご家族で話し合う際は…」

使える書式（リッチエディタ）

書式使い所
見出し2章タイトル（目次に載る）
見出し3章の中の小見出し
太字（strong）強調したい単語・キーフレーズ
斜体（em）やわらかい強調・思いを込めたい部分
引用お客様の声、印象的な一文
箇条書き選択肢や特徴の並列
番号リストステップや順序のあるもの
表比較・料金・スケジュールなど
画像本文の途中に挿入可（キャプションも付けられます）
リンク他の記事、サービスページへ
🌱 トーンオブボイス（大切な指針）

くらしのつむぎの記事は、"営業"ではなく"寄り添い"の言葉で書きます。

❌ 「今すぐ売却がおすすめです」「限定キャンペーン」
⭕️ 「まずは、ゆっくり考えてみませんか」「ご家族の状況によって、いくつかの選択肢があります」

8
CHECKLIST

デイリー運用チェックリスト

公開ボタンを押す前に、以下をご確認ください。慣れるまでは印刷して手元に置いておくのがおすすめです。

投稿前チェック

  • タイトルは40文字以内で、内容が伝わるか
  • スラッグ（URL用ID）は半角英数字か・意味が伝わるか
  • カテゴリは適切か（迷ったら「相続・税金・管理・活用」でOK）
  • 抜粋文は80〜120文字か・記事を読みたくなる文か
  • アイキャッチ画像は16:9で、内容と合っているか
  • 本文中の見出しは、H2から始まっているか（H1は使わない）
  • 誤字脱字はないか（プレビューで音読するとバグを見つけやすい）
  • 他ページへのリンクは正しく貼れているか
  • 「執筆者」欄は入っているか
  • この記事をピックアップにする場合、今表示中の別のピックアップをOFFにしたか

公開後チェック

  • 2〜3分後に本番サイトを開いて、記事が反映されているか
  • PCとスマホ両方で表示が崩れていないか
  • SNSでシェアするときは、記事URLをコピーして共有

FAQ｜よくあるトラブルと対処

Q. 記事を公開したのに、サイトに反映されません

A. まずは3分ほどお待ちください。それでも反映されない場合:

  1. Netlify の「Deploys」画面でビルドが走っているか確認
  2. ビルドが「Failed」になっていたら、ログを確認（APIキー切れが多いです）
  3. Webhookが正しく発火しているか、microCMSのWebhookログを確認

Q. 「Unknown category」というエラーがビルドログに出ています

A. カテゴリのvalue（英字コード）が、STEP 3で定義した5つ以外になっている可能性があります。microCMSでその記事のカテゴリを確認して修正してください。

Q. アイキャッチ画像を設定していない記事は、どう表示されますか？

A. サイト側で用意した4種類の装飾SVG（家/葉/コイン/ドキュメント）のいずれかが、記事のスラッグから自動選択されます。空欄でも画面が崩れることはありません。

Q. カテゴリを追加したいのですが？

A. 2箇所の変更が必要です。

  1. microCMS: category フィールドの選択肢に新しい英字コードを追加
  2. サイト: build/fetch-lab.mjs と data/articles.json の CATEGORIES 配列に、新カテゴリのオブジェクトを追加

2番目は開発担当への依頼が必要です。カテゴリ追加のご希望がありましたら、くらしのつむぎの制作担当までご相談ください。

Q. 過去の記事を修正したいです

A. microCMSの記事一覧から該当記事を開き、修正 → 「再公開」ボタンで、上書き公開できます。Webhookで自動的にサイトも更新されます。

Q. 記事を「非公開」にしたい

A. microCMSの記事画面右上「⋯」→「非公開にする」で、公開状態を解除できます。再度公開したくなったら「公開する」でOKです。

Q. APIキーが誰かに知られてしまったかもしれません

A. すぐに以下を実行してください:

  1. microCMS → サービス設定 → APIキー管理 → 該当キーを削除
  2. 「APIキーを作成」で新しいキーを発行（GET権限のみ）
  3. Netlify の環境変数 MICROCMS_API_KEY を新しい値に更新
  4. Netlify で「Trigger deploy」を実行して、新キーで再ビルド
