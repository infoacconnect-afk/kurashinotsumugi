## 実装

- 主要9ページのtitle/descriptionを検索意図に合わせて整理。見出し・確定済み本文・料金・納期・CSS・画像は維持。
- OGPはビルド時に最新のtitle/description/canonicalから生成。記事画像は既存の表示画像を使用し、画像URLを絶対URLにする。
- Organizationはcompany.htmlの表示中の会社名・住所・電話から取得。WebSite/WebPage/Service/BreadcrumbListを出力。未確認の対応地域・免許・口コミ評価・保証は追加しない。
- 記事の著者は表示中の著者名を使用。既存Article情報、初期HTML、正規URL、XMLサイトマップと併せて配信。
- 記事末尾の追加案内は、上記のとおり内容に対応するものを選ぶ。同じ既存ボタン部品を使い、文字サイズを下げない。
- 5つのサービス／診断ページの相談リンクにservice引数を付ける。フォームは許可した5項目だけを引き継ぎ、同意欄は未選択。お客様は相談項目を変更できる。引継ぎのみでは入力開始イベントも問い合わせも発生させない。
- 社内作業用docs/AGENTS.mdは配信対象から除外。
- FAQは既存の質問と回答を読めるHTMLとして維持。AI対策のためだけの大量記事、キーワード詰め込み、根拠のないFAQリッチ表示の約束はしない。

## 本番承認後・継続運用に残る事項

1. 承認後に本番を公開し、実際の本番HTTP応答・robots・canonical・サイトマップを確認する。試用URLは検索に登録しない。
2. Search Consoleのサイトマップ送信・URL検査・生成AI機能の設定状況は、接続ツールで確認できていない。完了とは扱わない。公開後の確認項目として扱う。
3. 実際の検索語句が出たら、この対応表と突合する。表示されるがクリックされない場合は説明の一致、訪問されるが相談に進まない場合は内容・案内・フォームの負担を調べる。少数のデータで断定しない。
4. 既存の週次レポート（毎週月曜、日曜までの速報）にはGSC検索語句・ページ別、GA4流入・問い合わせ、改善案が既に含まれている。2026-10-26に有効状態を確認。今回新しい重複タスクは作らない。
5. コンテンツ追加は実際に不足する質問と確認できる事例から行う。未確認のお客様の声・実績・専門資格・事例の掲載許諾を創作しない。
6. Core Web Vitalsの実利用者データ、スマホ実機、実際の問い合わせメール受信、AI回答内の掲載は未確認。ローカルの画面検査と同一視しない。
7. Windsor.aiは無料試用であり、期限後の継続取得は別途確認が必要。有料契約は行わない。
